# 04 · 项目测试要求

适用版本：v1.0.0 起。本文档是定版（release）测试的准入规范。

## 1. 定版准入（release gate，三条缺一不可）

1. 本次定版**新增/变更功能**必须已补充测试案例（正反例）并实现自动化
2. **全量自动化测试必须通过**：0 失败、0 错误；允许的跳过仅限
   “真实上游 API 冒烟”（默认跳过，避免消耗付费配额）
3. 已生成 Markdown 测试报告并存入 `docs/reports/`

不满足任一条，不得提交定版 commit、不得打 tag、不得推送 release。

## 2. 执行方式

```bash
docker exec astrbot python3 \
  /AstrBot/data/plugins/astrbot_plugin_oil_price/tests/test_oil_plugin.py
```

- 直接执行测试文件：自动清理隔离目录 → 运行全量 → 生成
  `docs/reports/测试报告_v<版本>.md` → 有失败时退出码为 1
- 真实 API 冒烟（可选，消耗付费配额）：`OIL_LIVE=1` 环境变量开启

## 3. 数据隔离（硬性要求）

- 所有测试读写 `/tmp/oil_plugin_test/`，**禁止**读写生产配置/历史/配额
- 每个测试用例独立的子目录，用例开始前清理
- 每次正式定版测试前：备份真实 config/history/quota 至带版本号的备份目录并记录 md5；
  测试完成后校验 md5 一致，不一致必须立即从备份恢复并查明原因

## 4. 覆盖要求（正反例）

| 领域 | 必须覆盖的正例 | 必须覆盖的反例 |
|------|----------------|----------------|
| 配置校验 | 合法全字段、边界时间、多选去重、目标规范化 | 空省份/非法省份、非法时间、非法限额、空 payload |
| 目标限额 | 目标绑定限额、留空回退全局、跨目标隔离 | 负数/非整数限额、无法识别的目标 ID |
| 指令 | 7 条指令的正常路径 | 无数据、接口失败、配额超限、非法升数、appKey 门控 |
| 推送 | 单省双消息、多省单长图、月报有数据 | 出图失败回退、全部查询失败不推、无数据月报跳过 |
| 数据源 | 正常响应规整 | 空 appKey、平台错误、业务错误、网络异常 |
| 存储 | 写读一致、趋势/月度序列、去重 | 跨缺口取数、窗口过滤 |
| 渲染 | 全油种、油号过滤、多线折线图 | 某省无数据、空数据占位 |
| 回归 | 真实事件 API（chain_result/plain_result） | 真实 schema 保存重载后动态限额键不丢失 |

## 5. 手工验收（不自动化，定版时逐项确认）

- TC-A16 真实 QQ 发送全部指令，回复正常
- TC-A17/TC-F10 出图在 QQ 客户端清晰可读，涨红跌绿
- TC-B08 真实目标收到推送，格式符合 FR-2.2
- TC-C17 WebUI 设置页加载、修改、保存闭环
- TC-D05 Dashboard 内三个 Web API 实际调用
- TC-G06 真实 ShowAPI 冒烟（记录执行人与消耗）

手工用例需记录：执行人、日期、环境、结论。

## 6. 测试报告必备字段

1. 版本号、执行时间、执行环境（Python/AstrBot/Pillow 版本）
2. 总用例数、通过/失败/错误/跳过计数与定版结论
3. 逐用例结果表
4. 失败详情（如失败，必须先修复再重跑至全绿）
5. 跳过原因说明
6. 本次定版新增/变更功能对应的新增用例编号

## 7. 红线

- 测试不得读写生产 `config/history/quota`（隔离目录之外零写入）
- 提交/报告内不得出现真实 appKey、QQ 号、群号、服务器地址
- 全量测试未通过时，禁止 commit 定版、禁止打 tag、禁止推送
